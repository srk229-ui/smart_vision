# 项目协作约定

## 项目重启与上下文恢复

- 每次开始新会话、项目重启或交接后继续工作，在修改文件或领取任务前，必须先阅读以下文件：
  - [TODO.md](demo/docs/TODO.md)，位置：`D:\镜头组\demo\docs\TODO.md`。恢复任务编号、状态、依赖、负责人、验收条件及证据。
  - [IMPLEMENTATION_REPORT.md](demo/docs/IMPLEMENTATION_REPORT.md)，位置：`D:\镜头组\demo\docs\IMPLEMENTATION_REPORT.md`。恢复总体架构、功能实现、公共接口、代码索引、验证结果及已知限制。
- 同时阅读 [MILESTONES.md](demo/docs/MILESTONES.md) 与 [REVIEW_LOG.md](demo/docs/REVIEW_LOG.md)，确认当前阶段、后续门槛、重要决策和固件／参数基线。
- 核对当前工作区差异与相关代码、证据，保留已有用户修改；若文档与实际实现不一致，先查明并记录差异，再继续受影响任务。
- 恢复上下文后，只推进依赖已满足的任务。已验收任务仅在新证据显示问题时重开；待实机项必须取得现场证据后才可关闭，未通过的里程碑门槛不得跳过。
- 主代理统一维护任务状态、复核记录和实现报告。继续工作时，先简要说明当前阶段、未完成事项及本轮准备执行的任务。

## 中文注释

- 新增或修改的代码注释使用中文，采用与项目现有工程一致的形式。
- 普通逻辑说明采用 `// 中文说明`；硬件初始化分组沿用 `/* 外设名称 */` 等原有写法。
- 公共接口和较复杂函数沿用逐飞库的函数说明形式，写清“函数简介、参数说明、返回参数、备注信息”，需要时补充使用示例。
- 注释说明代码用途、硬件约束和关键判断，不逐行重复明显的代码行为。
- 用户选定的行级注释范围为本轮新增/修改的固件代码（主循环、中断、控制、相机、视觉、PI和WIFI相关改动）；默认理解C基础，关键逻辑需解释变量来源/去向、复合条件各项、公式各项与单位、状态变化、边界及中断同步。长解释放代码上方，行尾写短含义/单位，复杂流程编号分段；保留函数说明和已有字段/宏注释。
- 公共结构体的每个成员、每个宏及枚举值均须有具体中文注释，说明含义；存在单位、方向符号、范围、占位值或状态限制时一并写清，避免把控制命令写成已实测物理量。
- API 名称、宏名、协议名、型号和必要的技术标识保留原文，例如 WIFI-SPI、TCP Server、WIFI6B21-SPI V2.0。
- 保留原有版权及许可证声明。修改文件时保持原有编码和换行方式，不为修改注释而批量格式化无关代码。

## 工程范围

- 当前使用工程为 `demo/mdk/rt1064.uvprojx`，其逐飞库位于根目录 `libraries`。
- `20th_smart_vision` 是参考工程，未明确要求时不改动其中的代码。
- WIFI-SPI 硬件使用 WIFI6B21-SPI V2.0（ESP32-C6）；电脑端使用逐飞助手 V1。模块驱动版本与上位机协议版本分别核对。
- 修改通信接入后，检查模块中断回调、工程文件注册及编译结果；未经实机测试不得声称通信已经验证成功。


## 仓库文档与时序说明

- 仓库Markdown报告中的源码索引面向VS Code内置Markdown编辑器，使用相对报告目录的文件路径与 `#L行号`；函数名和行号同时显示为可见文字。使用实际定义生成并校验，源码调整后同步更新索引。
- 实现报告按功能参考`20th_smart_vision/docs/完整闭环代码解析.md`的拆解层次，说明实际入口/调用顺序、关键函数输入输出、持久状态、公式单位、正常和失败分支；每个功能章节须有就近的真实函数定义索引，保留全局查找表。源码变化后同时刷新章内与总表行号，教学算例和软件/实机证据分别标明。
- 架构与状态机说明须区分主循环、采集回调、PIT任务、软件状态变化、PWM寄存器写入及引脚生效时间；实测未知项明确记录为待验证。
- 时序图和时间预算图中的数字须区分代码已配置周期、软件预算、教学假设和实测值；由假设计算的余量/生效时刻标为推演，已配置值也不能写成实测通过。图内数字附近与图例均明确标识。
- 调整控制周期前先实测执行耗时、抖动、漏周期、编码器量化和保护延迟；同步核对速度单位、Ki秒制、时间来源、斜坡、舵机变化率及相关测试，保留可恢复基线。
